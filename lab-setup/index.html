Lab Setup Guide

Each course has its own self-contained Docker lab. Download only the lab zip for the course you want to practice, run the included readiness check, start it with docker compose up -d, and work directly in browser terminals.

1. Download a Course Lab

Every zip file extracts into its own folder containing docker-compose.yml, container definitions, config.env, readiness scripts (check.sh & check.ps1), and a README.md. Each lab uses its own default port, so you can keep them side by side without conflicts.

2. Prerequisites

Nothing is installed on your host beyond Docker. Every lab binds strictly to 127.0.0.1 so it is reachable only from your own machine.

Docker Runtime

  • Windows: Docker Desktop with the WSL 2 backend (Linux containers).
  • macOS: Docker Desktop (Apple silicon or Intel).
  • Linux: Docker Engine with Compose v2.17+ and Buildx plugins, or Docker Desktop.

Machine Resources & Network

  • Memory: 4 GB allocated to Docker recommended (2 GB min for Ansible & Observability, 3 GB min for Kafka).
  • Disk space: ~5 GB free per lab for locally built container images.
  • Internet access (first build): pulls public base images from docker.io and quay.io.

3. Step-by-Step Setup

1

Unzip the lab archive

Extract the downloaded zip file (for example ansible-lab.zip) and open a terminal inside the extracted folder:

bash (Linux / macOS)
unzip ansible-lab.zip
cd ansible-lab
PowerShell (Windows)
Expand-Archive .\ansible-lab.zip -DestinationPath .
cd .\ansible-lab

Replace ansible-lab with apache-kafka-lab or observability-lab for the other courses.

2

Run the readiness check

The check installs nothing—it verifies Docker, Compose v2, Buildx, memory, disk, port availability, and registry connectivity, and writes .env from config.env.

bash (Linux / macOS)
./check.sh
PowerShell (Windows)
powershell -ExecutionPolicy Bypass -File .\check.ps1

Fix anything marked FAIL; lines marked WARN are advisory.

3

Start the lab

Run Docker Compose from inside the lab folder. The first start builds the local container images (takes a few minutes); subsequent starts take seconds.

Terminal
docker compose up -d
4

Open the lab in your browser

Open the local URL for your running lab—you will get browser terminals on every machine in the topology:

Course LabDefault URLIncluded Web UIs
Ansiblehttp://localhost:28201Browser terminals + /web/<node>/ proxy
Apache Kafkahttp://localhost:28202Browser terminals (3 brokers, producer, consumer, connect)
Observabilityhttp://localhost:28207Browser terminals + /grafana/, /prometheus/, /alertmanager/

4. Changing the Default Port

If another program already uses a lab's default port, edit config.env inside the lab folder:

config.env
LAB_PORT=28301
Important: After editing config.env, re-run ./check.sh (or check.ps1) so the new port is validated and written to .env, then run docker compose up -d to apply it. Use your custom port wherever the course lessons show the default.

5. Day-to-Day Commands

Run these commands inside the extracted lab folder (e.g. ansible-lab, apache-kafka-lab, or observability-lab):

What you want to doCommand
Pause the lab, keeping your work & volumesdocker compose stop
Resume a paused labdocker compose up -d
Check container status / view logsdocker compose ps / docker compose logs <service>
Reset the lab to a completely fresh statedocker compose down -v && docker compose up -d
Rebuild after downloading a newer lab zipdocker compose up -d --build
Remove containers, volumes, and local lab imagesdocker compose down -v --rmi local

6. Troubleshooting

Port already in use

Stop the service holding the port, or change LAB_PORT in config.env, re-run ./check.sh / check.ps1, and run docker compose up -d.

permission denied on Docker socket (Linux)

Add your user to the docker group with sudo usermod -aG docker $USER, then log out and log back in (or run newgrp docker).

Docker Hub pull errors or toomanyrequests

Docker Hub rate-limits anonymous pulls per IP address. Wait a few minutes or run docker login with a free Docker Hub account, then re-run docker compose up -d.

A lab machine shows a red status dot

The container may still be booting. Wait a few seconds, or inspect with docker compose ps and docker compose logs <machine>. A fresh reset (docker compose down -v && docker compose up -d) restores clean machines.
